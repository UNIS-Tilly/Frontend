## 7. 백엔드가 명세와 다르게 해석한 곳 (확인용)

답변이 모호해서 제가 해석한 부분입니다. 틀렸다면 알려 주세요.

| 항목 | 제 해석 |
|---|---|
| #19 "선택 0개: 해당 페이지에서 이동하거나 나가기" | 버튼은 서버 호출 없이 이동만 한다고 해석했고, 서버는 빈 선택을 400 `NO_ACTION_SELECTED`로 거절 |
| #12 "아카이브에서도 보임" | `DRAFT`가 있는 날도 아카이브 캘린더의 "기록 있음"으로 표시 (자동저장만 있는 날은 제외) |
| RC-02 "홈 체크리스트와 동기화 여부" | 같은 할 일 데이터를 공유 (RC-03이 "HM-04와 같은 데이터"라고 명시) |
| D-49 "5분 전 알림" | 서버 알림이 아니라 기록 화면 안의 인앱 안내로 해석 (사용자에게 재확인 완료) |
| D-44 "발행 전까지 수정 가능" | 해당 주 인사이트가 `PUBLISHED`가 되면 그 주의 기록과 할 일이 잠긴다고 해석. 새 할 일 모델에서는 "배정일 또는 완료일이 그 주에 속하는 할 일"로 구체화(Q-12). 인사이트가 없거나 `FAILED`면 잠금 없음 |
| D-54 "기록 부족 경고" | 응답의 `warnings` 필드로 전달하고 문구는 프론트가 표시한다고 해석 |
| 수정사항 "재직 직군" / "현재 인턴 직군" / "주 퇴근 시간" | 각각 같은 필드(`currentJobGroup`)·기존 `workEndTime`로 해석 |
| 수정사항 "배정일 우선으로 보여주되 지나면 계속 보여줌" | 배정일 ≤ 조회일이면 미완료인 동안 계속 노출(이월). 배정일 없음은 항상 노출. **마감일은 노출에 영향 없이 표시·지연 계산용** |
| 수정사항 "마감일이 남은 것은 모두 보여줘" | 위 규칙에 따라 노출은 배정일 기준이 되었고 "마감일이 남은 것을 배정일 전에도 노출"하지는 않는 것으로 해석 (확인 안 된 부분이라면 알려 주세요) |
| 수정사항 "하루 질문 API" | 회고가 아니라 **AI 확장 질문(최대 3개)과 답변**의 조회 API로 해석 |
| 수정사항 "발견한 강점/보완할 부분: 제목-세부 내용" | 기존 구조(제목·설명·태그·근거 칩)를 유지하는 것으로 해석 (태그·근거 칩 삭제 언급 없음, D-60) |

| 수정사항 "회원 수정 페이지 1에 나이" | 나이는 수정사항에 없었고 가입 1차 입력(닉네임·성별·나이)으로 새로 확인됨. 출생연도로 저장, 회원수정 항목에도 포함 |
