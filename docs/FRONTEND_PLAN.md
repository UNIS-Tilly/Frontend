> 작성일 2026-11-08 · 근거: 기능명세서(TILLY xlsx), PRD v0.2, 1011·1108 회의록, 1021 멘토링, 백엔드 저장소(`develop`, `feature/user` 브랜치) 코드
> 이 문서의 **일정과 우선순위는 제안**이며 팀 논의로 조정한다. 백엔드 사실은 코드에서 직접 확인한 것이다.

## 2. 기술 스택과 선택 이유

| 영역 | 선택 | 이유 |
| --- | --- | --- |
| 언어 | TypeScript | 백엔드 DTO를 타입으로 옮겨두면 필드 불일치를 실행 전에 잡아줌. AI 코드 검증에도 유리 |
| 빌드 | Vite 8 | 설정이 거의 없고 빠름. 서버 렌더링이 필요 없는 서비스라 Next.js는 불필요 |

| 통신 | fetch 래퍼 직접 구현 | 토큰 첨부·401 재발급·응답 언박싱을 한 파일(`api/client.ts`)에서 처리. axios 불필요 |

| 검사 | oxlint + Prettier | 템플릿 기본 + 포맷 통일 |
| 배포(제안) | Vercel / Netlify / Cloudflare Pages 중 하나 | 정적 사이트라 무료 티어로 충분 |

**의도적으로 쓰지 않는 것**: Redux/Zustand(서버 데이터는 TanStack Query로 충분), axios, UI 라이브러리(MUI 등 — 디자이너 시안과 싸우게 됨), Next.js, 테스트 프레임워크(MVP 기간에는 수동 확인 + 린트/빌드).
**나중에 필요할 때 추가**: Recharts(인사이트 달성률 꺾은선), date-fns(주/월 계산), MSW(mock 서버).

## 3. 백엔드 연동 정리

### 3.1 응답 형식
모든 응답이 `{ success, errorCode?, message, data }`. 프론트의 `apiFetch<T>()`가 `data`만 돌려주고, 실패 시 `ApiError`를 던진다.

### 3.2 인증 흐름 (이미 구현됨)
1. 로그인 화면 → 구글 로그인 화면으로 이동(인가 코드 방식, `state`로 CSRF 방지)
2. 구글이 `/auth/callback/google?code=…` 로 돌려보냄 → `POST /api/auth/login/google {code}`
3. 응답 `LOGGED_IN` → Access Token을 **메모리에 저장**, 홈으로 / `SIGNUP_REQUIRED` → `/signup`에서 닉네임 입력 후 `POST /api/auth/register`
4. Refresh Token은 HttpOnly 쿠키(경로 `/api/auth`)로 자동 관리. 새로고침 시 `POST /api/auth/reissue`(헤더 `X-Tilly-Client: web` 필수)로 로그인 복구
5. API가 401이면 재발급 후 한 번 재시도. 재발급도 실패하면 로그인 화면으로
6. 개발용: 백엔드 `local` 프로파일에서 `POST /api/auth/dev-login`으로 구글 없이 로그인 (로그인 화면의 "개발용 로그인" 버튼)

### 3.3 에러 코드 → 화면 처리 (백엔드 `ErrorCode` 기준)
| 코드 | 의미 | 화면 처리 |
| --- | --- | --- |
| `*_ACCESS_TOKEN`, `REFRESH_TOKEN_*` (401) | 인증 만료/없음 | 자동 재발급 → 실패 시 로그인 화면 |
| `*_SIGNUP_TOKEN` (401) | 가입 토큰 만료(30분) | "다시 로그인" 안내 |
| `GOOGLE_AUTH_FAILED` (502) | 구글 인증 실패 | 오류 메시지 + 재시도 |
| `TASK_LIMIT_EXCEEDED` (400) | 하루 할 일 개수 초과 | 추가 버튼 비활성 + 안내 |
| `RECORD_EMPTY` (422) | 기록이 비어 질문 생성 불가 | "먼저 기록을 남겨주세요" |
| `RECORD_LOCKED` (409) | 인사이트 발행된 주라 수정 불가 | 읽기 전용 표시 |
| `AI_GENERATION_FAILED` (502), `AI_TIMEOUT` (504) | AI 실패/지연 | 실패 안내 + 재시도 버튼 |
| `INSIGHT_WEEK_NOT_ENDED` (422), `INSUFFICIENT_RECORDS` (422) | 아직 분석 불가 / 기록 부족 | 이유를 설명하는 안내 화면 |
| `INSIGHT_ALREADY_PUBLISHED` (409), `NO_ACTION_SELECTED` (400) | 이미 발행 / 행동 미선택 | 안내 메시지 |

### 3.4 개발 환경 — CORS
백엔드에 **CORS 설정이 없다.** 개발 중에는 Vite proxy가 `/api`를 백엔드로 전달해서 브라우저 입장에서 같은 주소가 되므로 문제가 없다. 배포 시에는 아래 3.5를 결정해야 한다.

### 3.5 배포 시 주의
백엔드 쿠키는 운영에서 `Secure; SameSite=None`이다. 프론트와 API가 **서로 다른 도메인**이면 브라우저의 서드파티 쿠키 차단으로 로그인 유지가 깨질 수 있다.
- 권장 A: 프론트 호스팅의 rewrite/프록시로 `/api/*`를 백엔드로 전달 (브라우저는 같은 도메인으로 인식, CORS 불필요)
- B: 같은 상위 도메인의 서브도메인(`app.` / `api.`)을 쓰고 백엔드에 CORS(`allowCredentials`, 프론트 origin 명시) 추가
- 배포 구조는 백엔드 배포 방식(유료, 기간 미정)과 함께 결정해야 한다.

### 자동 저장 설계 (1108 회의 요구사항)
- 체크박스: 누르는 즉시 화면에 반영(낙관적 업데이트) → 서버 저장 → 실패 시 되돌리고 안내
- 텍스트(업무명·한 줄 메모): 입력 멈춘 뒤 0.8초 후 저장, 포커스 이동·화면 이탈 시 즉시 저장, `useAutoSave` 훅 하나로 공통화
- 하루 회고·확장 질문 답변: "임시저장" 버튼, "기록 완료하고 퇴근하기"로 확정

## 6. 팀에서 확인·합의가 필요한 것

**백엔드에게**
1. 할 일·기록·질문·인사이트 **API 명세서(마크다운)를 저장소에 공유**해 주세요. 없으면 `types/`를 확정할 수 없습니다. PR의 "프론트 영향"은 `FRONT_NOTICE.md`에 기록해 주세요.
2. **배포 구조**: 3.5의 A/B 중 무엇으로 갈지. (CORS 설정이 현재 없음)
3. **구글 OAuth**: 개발 Redirect URI `http://localhost:3000/auth/callback/google`을 구글 콘솔에 등록하고 Client ID를 공유해 주세요. 배포 도메인도 추가 필요.
4. **온보딩 필드**: 기능명세서는 성별·현재 직군·희망 직군·퇴근 시간·약관 버전인데, `register`는 닉네임만, `User`는 퇴근 시간만 저장합니다. 희망 직군은 AI 강점·개선 키워드 프롬프트에 쓰이므로 MVP에 포함할지 결정이 필요합니다.
5. **탈퇴 사유**: 명세서는 사유 입력, API는 `confirmEmail`만 받습니다.
6. **인사이트 주간 기준**: PRD는 "금~일에 사용자가 분석 요청"인데 에러코드에는 `INSIGHT_WEEK_NOT_ENDED`(아직 끝나지 않은 주)가 있습니다. 한 주의 시작/끝과 분석 가능 시점이 언제인가요?
7. **AI 응답 방식**: 질문 생성·분석이 동기 응답인지, 예상 소요 시간이 어느 정도인지(대기 UI 설계에 필요).
8. **기록 수정 정책**: 1108 회의는 "ver1 기록 수정 불가", 명세서는 업무 수정·자동 저장, 에러코드는 "인사이트 발행 후 잠금"입니다. 정확히 언제부터 수정이 막히나요?

**기획·디자인에게**
1. **PC 우선인지 모바일 우선인지**: PRD는 반응형(PC 우선순위 높음), 명세서의 다이얼 등은 모바일 UI입니다. 양쪽 시안이 필요합니다.
2. **디자인 토큰**(색·폰트·간격·모서리) 전달 — 현재 `index.css`의 색은 임시값입니다. 로딩·빈·오류 상태 시안도 필요합니다.
3. **확장 질문 방식**: 프론트 의견은 *v1은 사용자가 누르는 방식 + 설정한 퇴근 시간 10분 전에 홈에서 안내 배너로 유도*입니다. 서버 스케줄러가 필요 없습니다.
4. **개인정보·기밀 안내**: 인턴은 업무 내용을 적게 되므로(회사 기밀 가능), 기록 화면에 "회사 기밀·개인정보는 적지 마세요" 안내와 약관의 AI 처리 고지가 필요합니다. 무료 Gemini 사용 시 입력이 모델사에 공유될 수 있다는 점(1108 백엔드 공유)과 직결됩니다.
5. **메인 메타포 아이디어**: TIL → *till(밭을 갈다)* 말장난으로 **밭/정원**(기록=씨앗, 주간 인사이트=수확), 또는 **지층/나이테**(하루씩 쌓이는 층), **책장에 꽂히는 노트**.

## 7. 코드 읽는 법

**읽는 순서**: `main.tsx`(앱 시작) → `App.tsx`(URL↔화면 지도) → `api/client.ts`(서버 호출 규칙) → `providers/AuthProvider.tsx`(로그인 상태) → `pages/LoginPage.tsx`(화면 하나의 전체 흐름)

**Spring 비유**
| 프론트 | Spring에서 비슷한 것 |
| --- | --- |
| `pages/` | Controller + View |
| `components/` | 뷰 조각(fragment) |
| `api/` | 외부 API 호출 클라이언트 |
| `types/` | DTO |
| `App.tsx`의 `<Route>` | `@RequestMapping` 목록 |
| `RequireAuth` | Security 필터 |
| `AuthProvider` | SecurityContext |

**최소한 알아야 할 개념**
1. 컴포넌트 = 화면 조각을 반환하는 함수, JSX = 그 안의 HTML 비슷한 문법
2. props = 부모가 자식에게 넘기는 값 / state(`useState`) = 값이 바뀌면 화면이 다시 그려지는 변수
3. `useEffect` = 화면이 뜰 때/값이 바뀔 때 실행할 일
4. `useQuery` = 서버에서 가져오기(GET), `useMutation` = 서버에 보내기(POST/PATCH/DELETE)
5. Tailwind 클래스 = 스타일을 이름으로 붙이는 방식 (`p-4`=안쪽 여백, `md:`=PC 화면에서만)
6. TypeScript `type` = 데이터 모양 설명서

Claude에게 코드를 받을 때 쓸 질문: *"이 파일이 뭘 하는지 위에서부터 설명해줘. Spring 구조에 비유해서, 데이터가 어디서 와서 어디로 가는지 중심으로."*
