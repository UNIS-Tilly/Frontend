> 용도: ① 이번 기획 변경이 백엔드에 **어떻게 반영되는지**, ② 백엔드가 임의로 정한 **임시 값**, ③ 기획에서 **확인·확정해 주셔야 하는 질문**을 한 문서로 정리한 것입니다.

## 1. 이번에 반영한 기획 변경 (요약)

| 기획 변경 | 백엔드 반영 방식 |
|---|---|
| 회원 정보 확장 (성별, 재직 직군, 희망 직군, 얻고 싶은 역량, 성장 레벨) | 가입 때는 **닉네임·성별·나이**만 받고, 직군·역량은 **가입 직후 별도 화면(회원수정 페이지 1과 같은 저장 API)**에서 받습니다. 인증(로그인) 흐름은 그대로입니다 |
| 직군·역량은 정해진 키워드에서 선택 | 키워드는 서버 코드의 고정 목록으로 관리하고, 화면에는 선택지 조회 API로 내려줍니다. 직군 13개·역량 77개와 정의는 **확정**입니다 (3.2) |
| 역량 선택 규칙: 공통 역량 1개 이상, 희망 직군 역량 2개 이상 필수 | 희망 직군이 **선택 항목**이라 충돌했습니다. **희망 직군을 고른 경우에만** 그 직군 역량 2개 이상을 필수로 하고, 안 고르면 공통 역량 1개 이상만 검사합니다. 최대는 공통 3개·직군 5개입니다(확정) |
| 회원수정 페이지 1 (닉네임·성별·직군·역량) / 페이지 2 (퇴근 시간) | 페이지 1은 **일괄 저장 API 하나**, 페이지 2는 기존 퇴근 시간 저장 API를 그대로 씁니다. 기존 닉네임 단독 수정 API는 삭제합니다 |
| 회원 탈퇴: 가입 이메일을 입력해야 탈퇴 | 서버가 이메일 일치를 확인한 뒤 즉시 영구 삭제합니다. 구글 계정의 앱 연결 해제는 서비스에서 하지 않습니다 |
| 성장 레벨 1~9 (이미지는 프론트) | 서버가 레벨 숫자를 저장·내려줍니다. **퇴근 완료한 날이 하루 늘 때마다 +1, 9 다음은 1로 순환**합니다(확정, 3.1) |
| 할 일 = 그날 추가한 일만 (2026-11-24 변경) | 할 일은 **배정일(그 일을 추가한 날)에만** 보이고 **다음 날로 넘어오지 않습니다**(이월 없음). **마감 기한**은 넘기는 기준이 아니라 **오늘 기준으로 며칠 남았는지**("D-3", "D-Day", "D+2")를 보여 주는 용도이며, 서버는 남은 일수(`dueInDays`)를 내려줍니다 |
| 완료한 일은 없애지 않고 그날 완료로 기록, 완료/미완료 분리, "2/5" | 목록 응답이 **완료 목록 / 미완료 목록**으로 나뉘고 **완료 개수·전체 개수가 각각 숫자 필드**로 옵니다(프론트가 "2/5"로 표시) |
| 기록 화면 = 할 일(+메모) + 하루 회고 + 하루 질문, 각각 따로 조회 | 할 일 조회가 메모까지 내려주고, 하루 회고와 하루 질문은 각각 별도 조회 API입니다. 기존 "기록 상세 조회" API는 없앱니다 |
| 하루 회고 **복원** (2026-11-24 변경) | 하루 회고를 **다시 넣습니다.** 날마다 1건을 **별도 테이블**에 저장하고(2,000자 이하), **AI 인사이트의 입력·근거**로 씁니다(근거 칩 종류 "회고"와 "오늘의 회고 N개" 요약 칩 복원) |
| 아카이브 달력: 기록 유무만 | 그 달의 **모든 날짜**를 내려주고 날짜마다 기록 있음/없음만 표시합니다 (3.3) |
| 인사이트: 제목·소제목, 업무 달성 그래프, 이번주 업무 흐름 | 제목·소제목은 AI가 만들되 **숫자는 서버가 계산한 값과 일치하는지 검사**합니다. 그래프는 **월~일 7일 전체**, 흐름은 **같은 달 1주차~해당 주차**입니다 (3.3) |
| 인사이트 "추천 행동" (2026-11-24 확정) | 추천 행동은 **홈 화면에 보여주기만** 하고 할 일로 반영하지 않습니다(기획 화면 1-1 home). 반영 API·반영 토스트는 만들지 않습니다 |
| 인사이트 목록 조회 | 신규. 기획 화면(4-1 insight-home)대로 확정: 발행된 주만, 제목·소제목·기간, 최신순/오래된순, 20개씩 |
| 인사이트 분석 요청 시점 (2026-11-24 확정) | **금요일(퇴근 완료 후)·토요일·일요일에만** 요청할 수 있고 요청한 이번 주(월~일)를 분석합니다. 홈 인사이트 카드는 가장 최근에 발행된 인사이트입니다 |
| AI를 GPT 무료 모델로 변경, FastAPI 사용 여부 | 서버(Spring)가 GPT를 직접 호출합니다. FastAPI 서버는 두지 않습니다 (나중에 필요하면 교체 가능한 구조) |

## 3. 현재 임시 구현 내용 (기획 확정 시 교체)

### 3.1 성장 레벨 `[확정]` (2026-11-24, D-143)

- 가입 직후는 레벨 1입니다. **퇴근 완료한 날이 하루 늘 때마다 레벨이 1 오르고, 9 다음은 다시 1로 돌아갑니다**(순환). 새 날짜가 처음 퇴근 완료될 때만 계산합니다.
- "기록 하루"는 퇴근 완료한 날로 해석했습니다(임시저장만 한 날은 제외). 다르면 알려 주세요.
- 이미지(흙 → 새싹 …)는 프론트가 레벨 숫자로 매핑합니다. 이전 임시 구간표(0/1/3/7/14/30/60/100/150일)는 폐기했습니다.

### 3.2 키워드 목록 `[확정]`

### 3.3 동작 규칙 정리 (대부분 확정, 구현 순서대로 반영 중)

**회원**

| 항목 | 규칙 |
|---|---|
| 필수/선택 | 닉네임(2~10자) 필수. 성별·나이·재직 직군·희망 직군은 선택 |
| 역량 | 공통 역량 1~3개. 희망 직군 선택 시 그 직군 역량 2~5개. 희망 직군이 없으면 직군 역량은 선택 불가 |
| 나이 | 14~100 사이 정수 `[임시]` (입력값 그대로 저장, 해가 바뀌어도 늘지 않음) |
| 퇴근 시간 | 선택. 비우면 자동 질문 생성을 하지 않음 (기존 규칙 그대로) |

**할 일**

| 항목 | 규칙 |
|---|---|
| 날짜 | **배정일(필수, 생략하면 오늘)**·마감(선택, 날짜+시간). 마감과 배정일의 선후는 검사하지 않음 |
| 보이는 조건 | 할 일은 **배정일(그 일을 추가한 날)에만** 보임. 완료·미완료와 관계없이 다음 날로 넘어오지 않음(이월 없음). 완료한 일도 그날 목록에 완료로 남음 |
| 마감 표시 | 마감은 보이는 조건과 무관. **오늘 기준 남은 일수**를 알려줌(D-3·D-Day·D+2, 완료·마감 없음은 표시 없음) |
| 개수 제한 | 배정일별 **하루 20개**(완료 포함) |
| 메모 | **할 일마다 1개**(500자) |

**기록**

| 항목 | 규칙 |
|---|---|
| 하루 회고 | **날마다 1건**(2,000자 이하, 필수 아님), **별도 테이블**에 저장. 비우면 삭제. AI 질문·인사이트의 입력이 됨 |
| 질문 생성 | 그날 할 일이 1개 이상이거나 회고가 있으면 메모 없이도 생성. 퇴근 10분 전 자동 생성도 같은 조건 |
| 아카이브 | 기록 있음/없음만 표시 (임시저장·퇴근 완료한 날) |

**인사이트**

| 항목 | 규칙 |
|---|---|
| 요일별 그래프 | 월~일 7일. 요일마다 "그날 추가한 할 일 중 완료한 개수"와 "그날 추가한 할 일 개수" |
| 주 전체 | 전체 N개 = 그 주에 추가한 할 일 수(이월 없음), 완료 M개 = 그 중 완료한 수 |
| 이번주 업무 흐름 | 같은 달의 1주차 ~ 해당 주차 (월요일이 속한 달 기준, 예: 11월 3주차 → 1·2·3주차) |
| 제목·소제목 | AI 생성. 숫자는 서버가 계산한 값과 일치해야 함. 지난 주 기록이 없으면 비교 문구 없음 |
| 보완 톤 | 단정하지 않는 표현 (기존 원칙 유지) |
| 추천 행동 | **홈 화면에 표시만**(가장 최근 발행본의 추천 행동, 최대 2개). 할 일로 반영하지 않음 (D-147) |
| 잠금 | 인사이트가 발행된 주의 할 일·회고·기록은 수정 불가(할 일은 배정일 기준) |
| 분석 요청 시점 | **금요일(퇴근 완료 후)·토요일·일요일에만, 이번 주(월~일)를 분석**. 퇴근 완료 3일 이상. 놓친 주는 요청 불가. 발행되면(생성 중 포함) 그 주 전체가 잠김 |
| 할 일이 0개인 주 | 회고·메모·답변이 하나라도 있으면 분석, 모두 없으면 거절 |
| 인사이트 목록·홈 카드 | 목록은 발행된 주만 최신순/오래된순 20개씩. 홈 카드는 가장 최근에 발행된 인사이트 |
| AI 입력 | 할 일 제목·메모·**하루 회고**·질문 답변과 서버가 계산한 주간 수치, **희망 직군·선택 역량과 그 정의**(제안) |
| 강점 | 희망 직군 역량 중 기록에 구체적 행동 근거가 있는 것만, 가장 두드러진 것 (확정, KEYWORD_DEFINITIONS 1장) |
| 개선 | 부족을 단정하지 않고 STAR 중 약한 부분(상황·과제·행동의 이유·성과 수치)의 기록 보완을 제안 (확정) |
