# TILLY 기획 공지 (백엔드 → 기획)

> 작성일: 2026-11-12 · 작성: 백엔드
> 용도: ① 이번 기획 변경이 백엔드에 **어떻게 반영되는지**, ② 백엔드가 임의로 정한 **임시 값**, ③ 기획에서 **확인·확정해 주셔야 하는 질문**을 한 문서로 정리한 것입니다.
> 기획 확정 사항이 바뀌면 이 문서의 3장 값만 바꿔 주시면 되도록 백엔드는 해당 값을 한곳에서만 관리합니다.
> 이 문서는 개발 문서(`guideline/`)와 같은 비공개 문서입니다. 퍼블릭 레포에 올리지 않습니다.

## 1. 이번에 반영한 기획 변경 (요약)

| 기획 변경 | 백엔드 반영 방식 |
|---|---|
| 회원 정보 확장 (성별, 재직 직군, 희망 직군, 얻고 싶은 역량, 성장 레벨) | 가입 때는 **닉네임·성별·출생연도**만 받고, 직군·역량은 **가입 직후 별도 화면(회원수정 페이지 1과 같은 저장 API)**에서 받습니다. 인증(로그인) 흐름은 그대로입니다 |
| 직군·역량은 정해진 키워드에서 선택 | 키워드는 서버 코드의 고정 목록으로 관리하고, 화면에는 선택지 조회 API로 내려줍니다. 목록은 현재 **임시**입니다 (3.2) |
| 역량 선택 규칙: 공통 역량 1개 이상, 희망 직군 역량 2개 이상 필수 | 희망 직군이 **선택 항목**이라 충돌했습니다. **희망 직군을 고른 경우에만** 그 직군 역량 2개를 필수로 하고, 안 고르면 공통 역량 1개 이상만 검사합니다 |
| 회원수정 페이지 1 (닉네임·성별·직군·역량) / 페이지 2 (퇴근 시간) | 페이지 1은 **일괄 저장 API 하나**, 페이지 2는 기존 퇴근 시간 저장 API를 그대로 씁니다. 기존 닉네임 단독 수정 API는 삭제합니다 |
| 회원 탈퇴: 가입 이메일을 입력해야 탈퇴 | 서버가 이메일 일치를 확인한 뒤 즉시 영구 삭제합니다. 구글 계정의 앱 연결 해제는 서비스에서 하지 않습니다 |
| 성장 레벨 1~9 (이미지는 프론트) | 서버가 레벨 숫자를 저장·내려줍니다. 기준은 **퇴근 완료한 날의 누적 일수**이고 구간은 **임시**입니다 (3.1) |
| 할 일에 마감일이 생김 | 할 일은 **배정일(선택)**, **마감일(선택)**, **완료한 날**을 가집니다. 마감이 지나도 끝내지 못한 할 일은 계속 보이고 **"D+4"처럼 며칠 지났는지**를 내려줍니다 |
| 완료한 일은 없애지 않고 그날 완료로 기록, 완료/미완료 분리, "2/5" | 목록 응답이 **완료 목록 / 미완료 목록**으로 나뉘고 **완료 개수·전체 개수가 각각 숫자 필드**로 옵니다(프론트가 "2/5"로 표시) |
| 기록 화면 = 할 일(+메모) + 하루 질문, 각각 따로 조회 | 할 일 조회가 메모까지 내려주고, 하루 질문은 별도 조회 API입니다. 기존 "기록 상세 조회" API는 없앱니다 |
| 하루 회고 삭제 | 회고 입력·저장·인사이트 근거에서 모두 제거합니다 |
| 아카이브 달력: 기록 유무만 | 그 달의 **모든 날짜**를 내려주고 날짜마다 기록 있음/없음만 표시합니다 (3.3) |
| 인사이트: 제목·소제목, 업무 달성 그래프, 이번주 업무 흐름 | 제목·소제목은 AI가 만들되 **숫자는 서버가 계산한 값과 일치하는지 검사**합니다. 그래프는 **월~일 7일 전체**, 흐름은 **같은 달 1주차~해당 주차**입니다 (3.3) |
| 인사이트 "다음 주 추천 행동" 반영 | 반영한 할 일은 **배정일·마감일이 없는 할 일**이 되어 **완료할 때까지 매일 항상 보입니다**. (기존 "다음 주 월요일에 추가"는 폐기) |
| 인사이트 목록 조회 | 신규. 정렬 기준·화면 구성은 미정이라 질문에 포함했습니다 |
| AI를 GPT 무료 모델로 변경, FastAPI 사용 여부 | 서버(Spring)가 GPT를 직접 호출합니다. FastAPI 서버는 두지 않습니다 (나중에 필요하면 교체 가능한 구조) |

## 2. 기획에 확인·확정이 필요한 질문

우선순위 순입니다. "영향"은 답이 늦어질 때 막히는 것입니다.

### A. 구현을 막을 수 있는 것

| # | 질문 | 배경 / 백엔드의 임시 처리 | 영향 |
|---|---|---|---|
| P-1 | **직군·역량·성별 키워드 확정 목록**을 주세요. 직군별 역량은 몇 개씩인가요? 역량 **최대 선택 개수**가 있나요? | 지금은 임시 목록(3.2)으로 개발합니다. 이름(영문 코드)은 DB에 저장되므로 출시 뒤에 바꾸면 데이터 변환이 필요합니다. **출시 전에 확정**해 주세요 | 직군 선택 화면, 가입 후 입력 화면 |
| P-2 | **성장 레벨 구간**(몇 일 기록하면 몇 레벨)과 **산정 기준**이 맞나요? | 임시: 퇴근 완료한 날의 누적 일수로 계산, 한 번 오른 레벨은 내려가지 않음 (3.1) | 성장 메타포 이미지 매핑 |
| P-3 | **가입 직후 입력 화면(2단계)**에서 무엇을 받나요? 퇴근 시간도 포함인가요? **건너뛸 수 있나요?** | 임시: 가입 때 닉네임·성별·출생연도, 이어서 직군·역량(필수 규칙 있음). 건너뛰면 역량이 비어 있는 상태로 서비스를 쓸 수 있음 | 가입 플로우 와이어프레임 |
| P-4 | **나이**는 어떻게 받나요? | 개인정보 최소 수집을 위해 **출생연도**로 저장하고 선택 항목으로 둡니다. 화면에서 나이를 입력받는다면 출생연도로 환산하는 방식이 필요합니다 | 가입 화면 |
| P-5 | **인사이트 목록 화면**: 정렬 기준(최신순/오래된순 외), 한 줄에 보일 정보, 한 번에 몇 개씩 보일지, 분석 중·실패한 주도 목록에 보일지 | 임시 제안: 발행된 주만, 최신순/오래된순, 제목·소제목·주차 표시. 이 부분은 **구현하지 않고 기다립니다** | 인사이트 목록 |

### B. 화면·문구 확인

| # | 질문 | 배경 |
|---|---|---|
| P-6 | **할 일 추가/수정 화면**에 배정일·마감일 입력을 어떻게 넣나요? "배정일 없음(항상 보임)"을 사용자가 직접 고를 수 있나요? | 서버는 배정일·마감일 모두 비워둘 수 있습니다. 홈에서 날짜를 골라 추가하면 그 날짜가 배정일입니다 |
| P-7 | **지연 표시**는 "D+4"만인가요, 마감 전 "D-3"도 보이나요? 마감일이 없는 할 일은 어떻게 보이나요? | 서버는 마감이 지난 미완료 할 일에 "지난 일수"만 내려줍니다 (마감 전 D-n은 마감일로 프론트가 계산 가능) |
| P-8 | 할 일 목록은 **완료 목록 / 미완료 목록**을 한 화면에서 어떻게 나누어 보여주나요? | 서버는 두 목록과 완료·전체 개수를 따로 줍니다 |
| P-9 | **회고 삭제**로 사라지는 화면·기능을 알려 주세요 | 영향: 회고 가이드 선택(RC-04), 회고 입력·조회(RC-05), 홈 카드의 회고 표시, 인사이트 근거의 회고 종류. 기능명세서(xlsx) 갱신이 필요합니다 (4장) |
| P-10 | **질문 받기** 조건: 그날 보이는 할 일이 **하나도 없으면** 질문을 만들 수 없습니다. 이때 안내 문구는? | 할 일이 1개라도 있으면 메모가 없어도 질문을 만듭니다 (기존: 메모·회고가 비면 불가) |
| P-11 | **인사이트 "보완할 부분" 톤**: 기획 문구의 예시("~가 부족해요")는 기존 기획 원칙(IN-07: 부족하다고 단정하지 않기)과 충돌합니다. | 임시: **기존 원칙 유지**. AI가 "~를 더 기록하면 좋아요" 같은 완화된 표현으로 제목을 쓰도록 합니다. 예시 문구를 그대로 쓰고 싶으면 알려 주세요 |
| P-12 | **인사이트 그래프**: 월~일 7일 전체를 요일별로 보여주고 값은 "완료 개수/전체 개수"로 내려갑니다. 막대의 높이를 **비율(%)**로 할지 **개수**로 할지는 프론트가 정합니다. 맞나요? 지난 주 기록이 없는 첫 주는 비교 문구("지난 주 대비 …")를 **뺍니다**. 괜찮은가요? | 요일별 전체 개수는 그날 보이던 할 일 수입니다(이월 포함) |
| P-13 | **행동 반영 토스트**: "다음 주 월요일 체크리스트에 반영되었습니다"는 더 이상 맞지 않습니다. 반영된 할 일은 날짜 없이 **계속 보이는 할 일**이 됩니다. 문구와, 이 할 일이 목록 어디에 보이는지 안내가 필요합니다 | 중복 반영은 계속 허용(같은 행동을 다시 반영하면 할 일이 또 생김) |
| P-14 | **아카이브 달력**: 임시저장만 한 날도 "기록 있음"으로 표시하나요? | 임시: 임시저장 버튼을 누른 날과 퇴근 완료한 날을 "기록 있음"으로 표시. 자동저장만 된 날은 제외 |
| P-15 | **탈퇴 화면**(이메일 입력)과 **회원수정 페이지 1·2** 와이어프레임을 추가해 주세요. 탈퇴 시 구글 계정 연결은 직접 해제해야 한다는 안내 문구가 필요한가요? | 서버는 앱 연결을 해제하지 않습니다 |

## 3. 현재 임시 구현 내용 (기획 확정 시 교체)

### 3.1 성장 레벨 구간 `[임시]`

| 레벨 | 1 | 2 | 3 | 4 | 5 | 6 | 7 | 8 | 9 |
|---|---|---|---|---|---|---|---|---|---|
| 퇴근 완료한 날 누적 일수(이상) | 0 | 1 | 3 | 7 | 14 | 30 | 60 | 100 | 150 |

- 가입 직후는 레벨 1입니다. 퇴근 완료로 **새 날짜가 처음 완료될 때** 계산하고, 레벨은 내려가지 않습니다.
- 이미지(흙 → 새싹 …)는 프론트가 레벨 숫자로 매핑합니다.

### 3.2 키워드 목록 `[임시]`

**성별** (선택 항목, 선택 안 하면 비워둠): 남성(`MALE`) / 여성(`FEMALE`) / 기타(`OTHER`)

**직군** (재직 직군·희망 직군 공용): 개발(`DEVELOPMENT`) / 디자인(`DESIGN`) / 기획·PM(`PLANNING`) / 마케팅(`MARKETING`) / 데이터 분석(`DATA`)

**공통 역량** (모든 사용자, 1개 이상 필수): 의사소통(`COMMUNICATION`) / 협업(`COLLABORATION`) / 문제 해결(`PROBLEM_SOLVING`) / 시간 관리(`TIME_MANAGEMENT`) / 학습·적응력(`LEARNING_AGILITY`) / 문서화·보고(`DOCUMENTATION`)

**직군별 역량** (희망 직군을 고르면 그 직군의 역량 2개 이상 필수):

| 직군 | 역량 (코드) |
|---|---|
| 개발 | 코드 품질(`DEV_CODE_QUALITY`) / 디버깅(`DEV_DEBUGGING`) / 설계·아키텍처(`DEV_DESIGN`) / 버전 관리·협업 도구(`DEV_TOOLING`) |
| 디자인 | 시각 디자인(`DSN_VISUAL`) / 사용자 경험 설계(`DSN_UX`) / 프로토타이핑(`DSN_PROTOTYPING`) / 피드백 반영(`DSN_FEEDBACK`) |
| 기획·PM | 요구사항 정리(`PLN_REQUIREMENTS`) / 우선순위 판단(`PLN_PRIORITIZATION`) / 이해관계자 조율(`PLN_STAKEHOLDER`) / 지표 기반 의사결정(`PLN_DATA_DRIVEN`) |
| 마케팅 | 콘텐츠 기획(`MKT_CONTENT`) / 성과 분석(`MKT_ANALYTICS`) / 캠페인 운영(`MKT_CAMPAIGN`) / 고객 이해(`MKT_CUSTOMER`) |
| 데이터 분석 | 데이터 추출·SQL(`DAT_SQL`) / 분석·해석(`DAT_ANALYSIS`) / 시각화(`DAT_VISUALIZATION`) / 데이터 품질 관리(`DAT_QUALITY`) |

- 위 직군·역량 이름은 **백엔드가 개발을 위해 임의로 만든 것**입니다. 실제 서비스에 쓸 목록을 주세요(P-1).
- 재직 직군에 "기타" 같은 항목이 필요한지도 알려 주세요. (희망 직군은 소속 역량이 있어야 해서 "기타"는 둘 수 없습니다)

### 3.3 동작 규칙 정리 (현재 구현 예정)

**회원**

| 항목 | 규칙 |
|---|---|
| 필수/선택 | 닉네임(2~10자) 필수. 성별·출생연도·재직 직군·희망 직군은 선택 |
| 역량 | 공통 역량 1개 이상 필수. 희망 직군 선택 시 그 직군 역량 2개 이상 필수. 희망 직군이 없으면 직군 역량은 선택 불가 |
| 출생연도 | 1950년~올해 사이 숫자 `[임시]` |
| 퇴근 시간 | 선택. 비우면 자동 질문 생성을 하지 않음 (기존 규칙 그대로) |

**할 일**

| 항목 | 규칙 |
|---|---|
| 날짜 | 배정일(선택)·마감일(선택). 마감일은 배정일과 같거나 이후여야 함 |
| 보이는 조건 | 완료한 일: **완료한 날**에만 보임. 끝내지 못한 일: 배정일이 조회일 이전·당일이면 계속 보임(이월). 배정일이 없으면 끝낼 때까지 **언제 조회해도 보임** |
| 지연 | 마감일이 지났는데 끝내지 못했어도 계속 보이고, 마감일로부터 지난 일수(D+n)를 알려줌 |
| 개수 제한 | 배정일별 **하루 20개**, 배정일이 없는 미완료 할 일은 **별도로 20개** |
| 메모 | **할 일마다 1개**(500자). 이월되어 여러 날 보여도 같은 메모가 보임 |

**기록**

| 항목 | 규칙 |
|---|---|
| 하루 회고 | 삭제 |
| 질문 생성 | 그날 보이는 할 일이 1개 이상이면 메모 없이도 생성. 퇴근 10분 전 자동 생성도 같은 조건 |
| 아카이브 | 기록 있음/없음만 표시 (임시저장·퇴근 완료한 날) |

**인사이트**

| 항목 | 규칙 |
|---|---|
| 요일별 그래프 | 월~일 7일. 요일마다 "그날 완료한 개수"와 "그날 보이던 할 일 개수" |
| 주 전체 | 전체 N개 = 그 주에 한 번이라도 보였던 서로 다른 할 일 수(이월 포함), 완료 M개 = 그 주에 완료한 수 |
| 이번주 업무 흐름 | 같은 달의 1주차 ~ 해당 주차 (월요일이 속한 달 기준, 예: 11월 3주차 → 1·2·3주차) |
| 제목·소제목 | AI 생성. 숫자는 서버가 계산한 값과 일치해야 함. 지난 주 기록이 없으면 비교 문구 없음 |
| 보완 톤 | 단정하지 않는 표현 (기존 원칙 유지) |
| 추천 행동 반영 | 배정일·마감일 없는 할 일로 추가, 완료할 때까지 항상 보임. 같은 행동 중복 반영 허용 |
| 잠금 | 인사이트가 발행된 주의 할 일·기록은 수정 불가. 배정일이 없는 미완료 할 일은 잠기지 않음 |
| 분석 요청 조건 | 변경 없음 (주 종료 후, 퇴근 완료 3일 이상) |

## 4. 기능명세서(xlsx) 갱신 제안

기획 담당이 직접 갱신해 주세요. 백엔드는 xlsx를 수정하지 않습니다.

| 기능 ID | 제안 |
|---|---|
| RC-04 (회고 가이드) | 삭제 (회고 삭제) |
| RC-05 / RC-02 / RC-09 | 회고 관련 내용 삭제. "기록 화면 = 할 일+메모 / 하루 질문"으로 정리 |
| HM-02, HM-03 | 마감일·배정일, 이월, 완료/미완료 분리, 지연(D+n) 표시 추가 |
| HM-05, HM-07 | 할 일 추가·수정에 배정일·마감일 입력 추가 |
| CM-03, ST 영역 | 회원수정 페이지 1(닉네임·성별·직군·역량)·페이지 2(퇴근 시간) 추가. "프로필 설정 없음"(#6) 수정 |
| ST-03 | 이메일 입력 후 탈퇴로 확정, 화면 추가 |
| 가입 화면 | 닉네임·성별·출생연도 입력, 가입 직후 직군·역량 입력 단계 추가 |
| AR-01, AR-02 | 기록 있음/없음만 표시로 정리 |
| IN-03 | 변경 없음 |
| IN-07 | 톤 원칙 유지 확인 (P-11) |
| IN-09 | 반영 시점이 "다음 주 월요일"이 아니라 "날짜 없는 할 일로 항상 노출"로 바뀜. 토스트 문구 수정 (P-13) |
| (신규) | 인사이트 제목·소제목, 업무 달성 그래프, 이번주 업무 흐름, 인사이트 목록 |
| (신규) | 성장 레벨 표시 (홈 등 어디에 보일지) |
